# CONTROL-SCOPE-73／制御範囲と承認根拠の境界

2026-10-11。設計責任者・承認確認先：榊原純。AI-2026-044採番候補。未適用候補、024／043原本不変。実職員・技術主体・承認者の権限を発行しない。

## 確定事項と今回の判断区分

確定：初期対象は一般社団法人みらいの相談支援・GHフラワー・B型・事務本部・AI本部、GH拠点はコスモス・ダリア。他法人は初期対象外。権限管理担当は榊原純、ご自身の権限付与・拡大・停止解除は城戸裕子が承認、初期代理承認なし。業務肩書きとシステム権限は別管理。

設計案：通常の法人管理範囲ORG_CONTROLと法人横断の管理範囲PLATFORM_CONTROLを区別し、専用control_scopesで扱う。ORG_CONTROLからACCOUNT_GLOBAL操作を実行できる構造にしない。PLATFORM_CONTROLは型を用意するだけで、初期組織へ横断管理権限を与えるものではない。

未決：横断管理の実行主体・承認方法、初回認証許可承認者・初期技術資格・具体期間・取消手続、承認者権限失効／規則変更時の再審査。担当者の指定からこれらを推定しない。

## 物理候補

| 表 | 内容・制約 |
| --- | --- |
| control_scopes | 恒久範囲ID、scope_code、現在採用版、lock_version、作成actor／時刻。コード・ID・作成事実は不変、削除不可 |
| control_scope_revisions_73 | 同範囲の版番号／前版、管理種別、ACTIVE／STOPPED、CONFIRMED／UNVERIFIED、明示的global許容フラグ、適用期間、記録actor／時刻／根拠、sealed。同範囲版参照・番号一意 |
| control_scope_organizations_73 | 版ごとの明示対象法人。FKと複合PK。空集合を「全法人」と扱わない |
| control_scope_actions_73 | ORG_STOP／ORG_RELEASE／OS_STOP／OS_RELEASE／ACCOUNT_GLOBAL_STOP／ACCOUNT_GLOBAL_RELEASE／INITIAL_AUTH_ADMISSIONの明示許可操作。未知操作は拒否 |
| control_scope_systems_73 | 版・法人・system_codeの明示組合せ。同版の対象法人への複合FK。OSコードは完全一致で評価する |

組織・操作・OSの行は未封印の版へだけ追加する。追加時に版をロックし、封印との競合を直列化する。行の変更・削除、封印後の追加は禁止。対象を変更する場合は新しい版を作成し、明示対象集合全体を記録して封印する。

ORG_CONTROLは1法人だけを明示し、globalフラグはfalse。ACCOUNT_GLOBAL操作の列挙にはPLATFORM_CONTROLと明示globalフラグが必要。OS操作の列挙には明示OS対象が必要。これらは範囲の構造制約であり、実行する人の認可ではない。

現在版は同範囲の封印済み後継版へ、lock_versionを進めて採用する。直前の採用版を前版とし、記録版番号は前版より大きくする。未来開始の版は記録しても現在版へ採用できず、初回の現在版にも設定できない。未来の未採用版があっても、それを実施済みと扱わず現在版から新たな訂正版を記録できる。過去版への巻戻し、別範囲版への付替えは拒否する。

このモデルは制御範囲の「現在採用版」を表す設計案で、過去の人物・所属等のrevision_setsの方式を廃止するものではない。期間の履歴全体再解釈や予約採用処理は別工程。期限切れの記録は残し、現在範囲判定はfalseとする。

## 範囲判定と証跡の接続

scope_contains_73は、現在採用版・封印・ACTIVE・CONFIRMED・現在期間内、明示操作、明示法人／OS、管理種別とglobalフラグを確認するサーバー内部の構造判定。trueは「当該対象がこの範囲に含まれる」ことだけを示す。actorを入力に持たず、承認権限や実行資格を証明する関数ではない。

ORG／初回許可操作は対象法人必須・system_codeなし。OS操作は明示した同法人の同OSコードだけ。全体操作はorg／systemなしで明示PLATFORM_CONTROL・globalフラグ・対応操作を必要とする。法人内範囲へ全体操作を混在させない。globalフラグだけ、管理種別だけ、操作名だけで許可しない。

後段staff-control-scope-evidence-73.sqlで、新しい停止・解除・初回許可の作成時にも現在制御範囲を確認する。72の申請／操作境界整合に追加し、範囲外なら外側コミットを拒否する。制御範囲管理行の共有ロックを保持する。信頼できる適用処理では71のfence／全行ロック／ライブ時刻／リース・承認者確認が別途必要。

現在投影73は、初回許可の申請版が参照する範囲の現在法人・INITIAL_AUTH_ADMISSION包含も確認する。範囲縮小後に過去証跡を削除せず、初回認証だけの法人候補から除外する。正常な人物法人関係による通常業務候補は別条件で判定する。

既存の停止は、後から範囲が縮小・停止したことだけでは解除しない。停止／解除の履歴投影は66の全確定記録を維持する。全体停止の対象アカウントが将来複数法人に関係する場合、全影響法人を実行主体が管理できるかの認可は未実装であり、globalフラグだけで適用を開始しない。

## 初回承認方針の保留を実装する候補

initial_policy_readiness_73は、初回操作が範囲外ならSCOPE_DENIED、範囲内でもPOLICY_UNDECIDEDを返す。READY／許可を返す経路を用意しない。初回承認方針を採用するまで、範囲の成立だけで初回許可適用の入口を開かないための接続候補である。

この関数と専用適用処理はまだ実アプリへ接続していない。70／72／73の構造テストでは管理者が架空の判断・適用証跡を直接投入している。その成功を「初回承認方針が確定した」「正当な承認者が確認できた」と扱わない。実運用の適用入口は引き続き未実装・閉鎖状態。

## 承認根拠の検証契約案

decision_records.authority_evidence_refの非空チェックは承認権限の証明ではない。今後のauthorization_evidence／承認検証器は、次を専用FKと確認済み参照で結び付ける必要がある。

| 根拠 | 必要な確認 |
| --- | --- |
| 判断の対象 | 同じ申請版、変更種別、対象人物／アカウント、対象法人／制御範囲の版 |
| 判断主体 | 実認証で確認されたaccountとPERSON_ACCOUNT actor・人物の対応、判断時の有効状態。SERVICEの存在だけで人の承認を代用しない |
| 承認権限 | 採用済みの承認操作コードを許す専用grant版・scope版・依存関係。有効期間と対象包含。肩書き・役割任命から自動生成しない |
| 方針 | 判断時の採用済み方針版、自己操作の条件、代理条件。未決・未設定なら保留。初期代理承認は設定しない |
| 本人／自己操作 | 判断主体と対象人物の一致を恒久人物IDで確認。部署別表示IDや再発行accountによる別人扱いをしない |
| 導入例外 | bootstrapの承認対象・許可操作・scope・承認根拠・実行／認証根拠・結果・監査を固定。未決のbootstrapを通常権限の代用品にしない |
| 適用時 | 71の現在方針／対象版／fence／現在実行資格を確認。承認者失効・方針変更時の扱いは既存未決条件を保ち、勝手に再承認不要／必須としない |

検証器・grant正本と専用FK・bootstrap正本・現在認可fence・成功監査は未実装。任意JSON、自由文のADMIN、非空根拠文字列、APPROVEDという値だけを根拠にVERIFIEDを返さない。初回認証許可の承認者を001や016へ自動割当しない。既存の自己権限付与・拡大・停止解除の城戸裕子承認条件は維持する。
